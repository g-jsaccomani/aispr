# AI Security Posture Audit Checklist & Governance Baseline (2026)

This document defines the verification criteria and audit checklist for continuous assessment of the security posture of Artificial Intelligence environments and agentic workloads, in accordance with the **Google Secure AI Framework (SAIF)**.

---

## 1. Supply Chain Audit and Provenance (SLSA for AI)

- [ ] **1.1 Model Signature Verification**: Are the deployed language models sourced from trusted repositories and do they have verified cryptographic signatures (e.g., Sigstore / Cosign)?
- [ ] **1.2 Model Build Isolation**: Do pipelines that perform finetuning or process embeddings run on ephemeral clusters without access to the public internet?
- [ ] **1.3 Dataset Traceability (Provenance)**: Is there an auditable record (Metadata Store) of all training datasets, prompts, and RAG versions that make up each model version in production?

---

## 2. Input and Output Data Protection (DLP & Model Armor)

- [ ] **2.1 PII Inspection and Masking (Sensitive Data Protection)**: Is there an active DLP policy to mask SSNs, credit card numbers, and trade secrets before the data is submitted to Vertex AI or external models?
- [ ] **2.2 Anti-Injection Filters (Model Armor)**: Do the inference endpoints have real-time filters to automatically reject attempts of *Prompt Injection*, *Jailbreaking*, or *Hidden Context Exposure*?
- [ ] **2.3 Output Sanitization**: Are the outputs generated by LLMs properly handled/escaped before being consumed in APIs or executed in browsers/databases?

---

## 3. Agentic Security and Access Control (IAM & Zero Trust)

- [ ] **3.1 Least Privilege for Tools/Plugins**: Do AI agents have service accounts with granular minimum permissions only for the APIs and tables they need to query?
- [ ] **3.2 Mandatory Human-in-the-Loop (HITL)**: Do high-impact mutations (deletions in GCS, database changes, financial triggers) require explicit approval from an authenticated human operator?
- [ ] **3.3 Quotas and Resilience Limits**: Do the endpoints have strict Rate Limiting and token limitation to prevent Denial of Service (DoS) via *Unbounded Consumption*?

---

## 4. Compliance and Telemetry (Google SecOps)

- [ ] **4.1 AI Platform Logs Export**: Are prediction logs, access audits, and endpoint modifications in Vertex AI continuously exported to the Google SecOps SIEM?
- [ ] **4.2 Continuous Red Teaming Tests**: Does the environment undergo periodic rounds of automated Red Teaming against new classes of OWASP LLM Top 10 attacks?
