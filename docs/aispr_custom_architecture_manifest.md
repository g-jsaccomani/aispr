## 2. Core Google Security Foundations (Grounded in SAIF & Cloud CISO)

Based on Google Cloud and Mandiant AI security research, the architecture integrates the following core principles:

### A. Strong Security Foundations (IAM & Network Isolation)
* **Least-Privilege Identity:** Restrict model and pipeline access using granular IAM roles (`roles/aiplatform.user`, `roles/cloudkms.cryptoKeyEncrypterDecrypter`). Infrastructure discovery operates under custom, auditable read-only roles (`AIP Viewer`), eliminating administrative over-privilege.
* **Perimeter & Cryptographic Isolation:** Model inference APIs route privately via **Private Service Connect (PSC)**, eliminating public internet exposure. Training datasets and RAG stores are bound within a **VPC Service Controls (VPC-SC)** perimeter and encrypted with **Cloud KMS Customer-Managed Encryption Keys (CMEK)**.

### B. Active Defense & Semantic Filtering (Model Armor & DLP)
* **Semantic Edge Firewall:** Enforce input and output shielding rules via **Google Cloud Model Armor** with sensitivity thresholds configured to intercept prompt injection, DAN jailbreaks, and harmful payloads before consuming compute resources.
* **Automated Sensitive Data Protection:** Integrate Model Armor with Cloud DLP inspection templates to automatically de-identify and redact PII, tax IDs, and confidential credentials in real time.

### C. Insecure Output Handling & Human-in-the-Loop (HITL)
* **Output Sanitization:** Code snippets and SQL/API queries generated by LLMs are strictly validated before execution against internal databases or downstream APIs.
* **Human-in-the-Loop (HITL) Gates:** High-impact transactions (file deletions, financial approvals, IAM modifications) triggered by autonomous agents require cryptographic human authorization via single-use approval tokens.

### D. Continuous Threat Operations & Shadow AI Hunting
* **Shadow AI Discovery:** Automated scanning of Kubernetes clusters (GKE) and serverless runtimes for unapproved third-party LLM containers operating on exposed ports (e.g., Ollama on Port 11434).
* **CVE-2026-2244 Remediation:** Proactive inspection of Vertex AI Workbench instances to block insecure startup scripts and eliminate token leaks.
